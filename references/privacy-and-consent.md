# Privacy and consent

Reference photos can contain identity, location, device, and relationship information. Treat them as source material, not as reusable project assets.

## Rules

- Work only with photos the user owns or is authorized to edit.
- Do not add a real person’s photo, generated likeness, name, or identifying story to this repository, an issue, a pull request, a demo, or a public gallery without explicit permission for that specific publication.
- Do not claim that processing is local. The image may be sent to whichever image-generation provider the user or environment selects; provider terms and retention policies apply.
- Do not infer ethnicity, health, religion, sexuality, personality, or other sensitive traits from appearance. Describe only visible features needed to preserve likeness.
- For minors, use especially conservative handling and never publish source or output images without permission from the appropriate guardian and subject where applicable.
- Keep the source photo unchanged. Save generated results separately.
- Before publicly sharing a permitted image, remove unnecessary metadata such as EXIF location and device details.
- Never commit API keys, provider credentials, private image URLs, or prompt logs containing personal information.

## Safe examples

Use one of these for documentation and tests:

- A synthetic person created for the project.
- A self-portrait whose creator explicitly chose to publish it.
- A public-domain or permissively licensed portrait with attribution and license recorded.

The repository intentionally ships without a real-person demo photo.
